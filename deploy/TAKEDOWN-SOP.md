# 版权投诉与监管下架 SOP(#12 Eng review)

> 配套接口已实现: `deploy/README.md` §8 上线后运维 + 后端 `/admin/*` 管理接口
> (需配置 `ADMIN_API_KEY`,见 `backend/.env.example` / `deploy/.env.production.example`)。
> 本文档定义**流程**,接口只是执行面 —— 关键是人: 明确责任人与时限,避免漏处理。

---

## 1. 角色与责任

| 角色 | 责任 | 备注 |
|------|------|------|
| 运营/管理员 | 每日查 `/admin/health`(openReports 计数)、审举报、执行下架 | 唯一持有 `ADMIN_API_KEY` |
| 技术负责人 | 处理投诉邮件、协助批量下架、DB 恢复 | 与运营双人复核,避免误下 |
| 客服入口 | 接收用户举报(APP 内已有点位)+ 邮件投诉 | 举报数据即 `/admin/reports` |

---

## 2. 举报来源与处理时限

| 来源 | 入口 | 建议时限 |
|------|------|----------|
| 小程序内「举报」 | 详情页 → 更多 → 举报 → `/admin/reports` 审阅 | 24h 内初审 |
| 邮件/私信投诉(权利人) | 运营邮箱 | 48h 内响应,7 天内处理 |
| 监管(网信办/版权局)通知 | 书面渠道 | 立即响应,按通知要求时限 |

**原则**: 权利人投诉 = 优先暂缓展示(block),核实后再定夺;不要等证据链齐全才动作
(展示期间的传播已构成持续侵权风险)。

---

## 3. 处理流程(四步)

### 3.1 受理登记
- 小程序举报: 数据已落 `/admin/reports`(含举报人哈希、壁纸、reason),无需登记。
- 邮件投诉: 记录 投诉人 / 被投诉条目(sourceId 或 id) / 主张 / 联系方式 / 期望。

### 3.2 初审 → 暂缓(隔离)
- 只要投诉指向明确条目,立即执行:
  ```bash
  # 管理员接口(需 ADMIN_API_KEY)
  curl -X POST https://<domain>/admin/wallpapers/<id>/block \
    -H 'X-Admin-Key: <ADMIN_API_KEY>'
  ```
  效果: 信息流/搜索/详情/收藏列表全部下线(status=blocked),对外 404。
- 记录隔离原因与时间(日志/工单)。

### 3.3 核实(双人复核)
- **许可白名单复核**: 对照 manifest 中该条目的 `license` / `licenseUrl` / `creator` /
  `creatorUrl`(Wikimedia Commons 文件页一键核验)。收录时逐张核验过许可,此处复查
  是否收录环节出错(如 CC BY 但漏署名、来源标注错误)。
- **权利人证据**: 权利人主张 → 要求提供权属证明(登记证书/水印原图/发布记录)。
- **我方立场**: 白名单许可(CC0/CC BY/PD)且来源可核验的,可主张「已尽合理审查义务」,
  但仍尊重权利人诉求;许可存疑的,维持下架。

### 3.4 结案
| 结论 | 动作 |
|------|------|
| 确认侵权/许可存疑 | 保持 `blocked`;记录结案;回复投诉人 |
| 误报/证据不足 | `restore` 恢复展示(仅双人复核后);回复投诉人说明 |
| 监管通知 | 按通知要求执行;需要时同步配合调查,保留沟通记录 |

处理完成 → `/admin/reports/<id>` DELETE(幂等,记录移除)。

---

## 4. 监管下架(中国监管配合)

1. **收到通知**: 记录通知方、文号、时限、涉及条目。
2. **立即执行**: 全部涉事条目 `block`(可用 `backfill`/SQL 批量,但先单条验证)。
3. **留存证据**: 通知原文、处理时间、操作日志(审计)。
4. **回复**: 按通知要求反馈处理结果;无法确认的条目主动沟通。
5. **不改数据**: 监管下架只改 `status`(blocked),不删除记录 —— 保留审计可追溯,
   后续如需恢复必须重新核验。

## 5. 审计与留痕

- 所有 block/restore 动作记入操作日志(后端结构化日志带时间戳)。
- 建议定期导出 `/admin/reports` 处理记录归档(季度)。
- 上线前把本 SOP 文档 + 管理员账号归属写进运维交接文档。

---

## 6. 与广告/解锁的关系

- 下架不影响 `ad_unlocks` 历史记录(用户已解锁权益不追溯);
- 下架条目在收藏列表自动消失(join 时 status='active'),用户看到的是「内容已下架」的
  友好提示(前端已按 404 处理)。
